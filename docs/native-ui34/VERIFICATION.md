# 原生安卓 3.4 验证记录

最终体验 APK：`3.4.12-preview`，包名 `com.laolao.classcalendar.preview`，应用名称「捞捞课程表」。使用 JDK 17、Android 34 资源编译、D8（min API 24）构建，通过 APK v2/v3 签名验证。

设备验证使用 AOSP Android 9 / API 28 模拟器。框架读取实际 Android 控件层级、使用系统剪贴板、读取真实保存后的记录；没有把网页或假数据输出当成功能验证。

## 已验证的关键操作

- 原产品名称、五个主要导航，以及菜单中的班级墙、规划、成长和班级入口。
- 有正在进行的课程时，首页的「记一件事」仍然存在。
- 日历直接粘贴真实中文群消息，先到审核页；确认前不保存，确认后实际创建一条个人事项，时间正确。
- 保存后重启进程，记录继续存在，可在日历事项列表中找到。长列表的可见性检查会正常滚动到事项。
- 搜索 PDF 可以找到并打开原生扫描页面；十项手机能力保留原生入口。
- 原网页日历小人可以打开助手并从保存的课表回答问题。
- 关闭、重启、恢复首页提醒的偏好会持久保存；网站已有的助手 side/screen 设置仍保留。
- 常用工具的勾选、保存、取消、空选择、进程重启和快捷打开，以及学习数据保持不变。
- 320 dp 宽、1.5 倍字号下的关键选择按钮、固定保存/取消区域和独立滚动正文。

助手紧急程度计算另以相同输入对照仓库实际 `island-core.js` 与原生 Java 规则，8 个案例通过，包括过期作业、会议降权、考试、待确认和日期未知等。

源码检查确认原有 63 个原生 route 合约继续存在。这是保留入口的静态检查，不等同于对 63 页所有业务、权限与网络分支都完成实体机测试。设备运行结果见 reports 中的独立报告。

## 数据和边界

测试仅修改体验包模拟器中的隔离 guest 记录，结束时原 XML 字节、字体和动画设置均恢复。工具小屏测试还恢复显示尺寸和密度。测试剪贴板辅助 APK 不会随产品交付。

没有生产账号与华为实体机，因此本次没有宣称完成生产云端班级发布、实体手机通知/录音/定位权限组合测试。相关业务和系统绑定沿用已有原生实现。

网页首页和统计代码没有改动。源码覆盖包按仓库 `3f8d854` 汇总必要安卓修改，包含前后两轮所需的新原生类与配色资源，不包含签名密钥。source-files.json 提供逐文件摘要，更新文件清单提供完整交付摘要。
