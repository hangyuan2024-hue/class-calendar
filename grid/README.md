# 捞捞算力

几台电脑一起训练捞捞自己的模型（Q版形象、声音→表情、改 PPT）：**一台停了，下一台接着算**；电脑可以随时加进来；同事一用电脑就自动让出显卡；需要人看的（审核、录表情）大家都能做。

```
                ┌──────────── 调度中心（云服务器，server/）────────────┐
                │ 派活 · 记账 · 存进度（一个 SQLite 文件）· 控制中心网页 │
                └───────┬──────────────────────────────┬────────────┘
         领活 / 报平安 / 交结果（HTTPS）          临时上传 / 下载链接
                        │                              │
   ┌────────────────────┼───────────────┐      ┌───────▼────────┐
   │ 捞捞算力客户端（app/，Windows）        │      │ 腾讯云 COS      │
   │ 张三的台式机 · 李四的游戏本 · 你的电脑…  │◀────▶│ 存档、数据、图片 │
   │ 跑配方（Python），实时报代码行和曲线     │      └────────────────┘
   └───────────────────────────────────────┘
```

## 怎么做到「一台停了，下一台接着算」

- **租约**：领到任务的电脑每 20 秒报一次平安；2 分钟没消息，调度中心就把任务交给下一台。掉线不算任务的错（换 30 次电脑都没算完才放一边）；配方出错 5 次才放一边。
- **存档**：训练配方每隔几分钟调一次 `lg.checkpoint()`，客户端在后台上传；下一台从**最近的存档**接着算（包括优化器状态、步数、数据读到哪），最多丢几分钟。
- **三种分法**
  | 分法 | 用在 | 停了一台 |
  |---|---|---|
  | `map` 拆成很多小任务，谁空谁领 | 生成训练数据、跑评测 | 那个小任务转给别人重做 |
  | `relay` 接力：一次一台，分段算 | 小模型（声音→表情、改 PPT） | 下一台从最近存档接着算 |
  | `diloco` 多台一起训：每轮各自算一段，交上「改了多少」，合并成下一轮 | Q版插件（大一点的训练） | 这一轮不等它，到时间用交上来的几份合并；回来了下一轮再加入 |
  | `record` 人工：录表情 | 同事对着摄像头读讲稿 | 没录完的那段还是他自己的 |
- **断电测试**（`test/chaos.test.js`）：4 台模拟电脑真的跑 Python 配方，每 0.6～1.2 秒随机「拔电源」一台；检查接力训练的最终模型和一台电脑从头算到尾的**一位都不差**，DiLoCo 照样跑完、误差下降，生成的图都进了审核。

## 安全

- **配方签名**：配方（会在同事电脑上跑的 Python）必须由管理员用自己电脑上的私钥签名（ed25519）；邀请链接里带着公钥，客户端核对签名，不对就不跑——就算调度中心被人黑了，也没法让大家的电脑跑别的代码。
- **存储密钥只在调度中心**：各台电脑拿到的是有效期几小时的临时链接（COS 预签名），拿不到密钥。
- **隐私**：录表情时视频不保存、不上传，只上传每一帧的表情参数（`shared/expr.js` 的 14 个数）和录音；加入时要勾同意；客户端里随时能暂停、退出。
- **对同事友好**：默认「空闲 5 分钟才算」；有别的程序占着显卡（游戏、剪视频）就让；显卡超过 83℃ 先停；关窗口后藏到托盘，托盘里能暂停 / 退出。

## 上手

**1. 调度中心**（一台云服务器，腾讯云轻量 2 核 2G 就够）
```bash
git clone <仓库> && cd <仓库>
sudo bash grid/server/deploy.sh                          # http://服务器IP:8787
sudo DOMAIN=grid.你的域名.cn bash grid/server/deploy.sh   # 有域名：自动 HTTPS（推荐，家里的电脑走公网）
```
装完会打印控制中心地址和**管理员口令**。大文件放 COS：填 `/etc/laolao-grid.env` 里的 `GRID_COS_*`，`sudo systemctl restart laolao-grid`。

**2. 你自己的电脑**（管理员：签名配方、发任务）
```bash
node grid/tools/grid.js login https://grid.你的域名.cn <管理员口令>   # 生成签名密钥（私钥只在你电脑上）
node grid/tools/grid.js invite 张三                                  # 发邀请链接
node grid/tools/grid.js job grid/plans/demo.json                     # 按计划建任务（自动签名、上传配方）
```
控制中心（`/admin/`）也能发邀请、建任务、暂停、调优先级、看每台电脑实时跑到哪一行、导出审核结果。

**3. 同事的电脑**：装「捞捞算力」（Actions 里的「捞捞算力」工作流打包，Releases 的 laolao-grid），粘贴邀请链接加入，按任务向导：体检 → 一键装训练环境（Python 3.11 + PyTorch CUDA 12.8，装在软件自己的文件夹里）→ 跑通测试 → 装 AI 引擎（显卡 8G 以上：ComfyUI + Qwen-Image-Edit，约 35G，从国内存储下）→ 录表情（自愿）→ 什么时候算（默认：点「开始」才算）。你自己的电脑也可以装一个一起算。

## 写配方

```python
# requires: diffusers==0.35.1 transformers      ← 要的包（客户端自动 pip 装，走清华 / 阿里镜像）
import lg
t = lg.task()                      # {"input": 这个小任务的输入, "job": {"params": 任务参数}, "resume": 最近存档的本地路径, ...}
for step in range(...):
    lg.metric(step, loss=loss)     # 曲线（客户端、控制中心实时画）
    lg.progress(step / total)
    if step % 100 == 0:
        save(f"ckpt-{step}.pt"); lg.checkpoint(f"ckpt-{step}.pt", step)
lg.review(kind="ab", a="a.png", b="b.png", question="哪个更像本人？")   # 交给大家审核
lg.done(ckpt="final.pt", loss=loss)   # 结果里的文件会自动上传
```
示例：`recipes/demo_relay.py`（接力，断电后结果不变）、`recipes/demo_diloco.py`（多台一起训）、`recipes/demo_avatar.py`（生成 + 审核）、`recipes/probe_gpu.py`（测显卡）。

## Q版自动训练（`plans/qversion.json`，不定时间）

```bash
node grid/tools/grid.js cycle grid/plans/qversion.json          # 设好就开始：谁开着谁算
node grid/tools/grid.js cycle grid/plans/qversion.json --now    # 不等攒够审核，马上训练一次（控制中心也能点）
```
没有固定时间：同事想算就在软件里点「开始」，不想算点「停止」（正在算的交给别的电脑从存档接着算）。

| 步骤 | 什么时候 | 谁做 | 做什么 |
|---|---|---|---|
| 画 Q版（`recipes/qv_gen.py`） | 一直有活（`standing`），快领完了自动补 40 个 | 装了 AI 引擎、点了「开始」的电脑（显卡 8G+） | 随机一位「虚拟老师」的照片 → 老师端同款流程画 2 张 Q版 → 交审核（带参考照片）；每张图的 CLIP 特征跟着审核存 |
| 审核 | 随时 | 所有人（软件里「人工审核」，快捷键 1/2/3/0） | 哪张 Q版更好 |
| 训练打分模型（`recipes/qv_scorer.py`） | 新审核攒够 50 条、离上次至少 3 小时（`when`） | 任何一台（只用 numpy，几分钟） | 用到现在为止所有审核训练；和现在发布的那一版在同一份考题上比，答对得更多（且 ≥55%）才发布 `qversion-scorer` |

配方或发布的模型更新了，画图的活自动换成新的（正在画的画完）；一个都没画成就连着失败 5 个，自动停下等你看出错信息。

## 答题数据工厂（`plans/qa.json`，不定时间）

同事的 8G 显卡在本机跑本地大模型（llama.cpp 跟着安装包走，Vulkan 版；模型 Qwen3-8B Q4，约 5G，第一次自动下载，魔搭优先）做题、写「讲给学生听」的讲解，**自动核对，对的才留**：
- GSM8K（MIT）改写成中文 → 讲 4 遍 → 和标准答案对上的才留
- 按中国中小学数学知识点出新题 → 讲 4 遍 → 至少 3 遍答案一样才留

和「画 Q版」一样优先：几台电脑自动分开做（一台画图、一台做题），做完接着做自己那种（模型不用重新加载）；开大模型前先关 ComfyUI，反过来也一样（8G 显存放不下两个）。
留下的讲解以后用来微调老师端的答题大脑（Qwen3-VL-4B）。配方开头写 `# needs: llm`，任务参数 `llm` 写模型名和下载地址，配方从 task.json 的 `llm` 拿到本机地址（OpenAI 兼容）。

配方里要用本机的 AI 引擎：开头写 `# needs: comfy`，用 `lg.comfy("info" / "upload" / "lora" / "run", ...)`；训练要审核结果：任务参数写 `"dataset": "标签"`，配方里 `lg.dataset()`。配方改了直接 `cycle` 重新签名上传，客户端不用更新。

## 训练路线（8G 显存的 5060 × 3 + 你的电脑）

| 阶段 | 做什么 | 分法 |
|---|---|---|
| 1 · 数据 | 同事录表情（每人 30～60 分钟）；Z-Image 生成虚构人像；大模型（Qwen-Image-Edit-2511 / FireRed）画 Q版和表情图，自动打分 + 大家审核 | record、map |
| 2 · 小模型 | 「声音→表情」（几百万参数，按讲稿对齐嘴型，只学过渡和语气）；改 PPT（Qwen3-VL-4B QLoRA，数据程序生成、自动核对对错） | relay |
| 3 · Q版模型 | 「捞捞Q版」插件（大模型当老师出数据，Z-Image 6B 当学生，FP4 省显存） | diloco |
| 4 · 评测、开源 | 每个模型在评测集上超过现在的版本才发布 | map |

## 代码

| 路径 | 做什么 |
|---|---|
| `server/core.js` | 调度中心的核心：成员、电脑、邀请、任务、租约、存档、审核投票、积分（`node:sqlite`） |
| `server/index.js` | HTTP 接口、存储（本机 / COS 预签名）、配方签名核对、控制中心网页（`server/admin/`） |
| `server/deploy.sh` | 在云服务器上一键装好（Node 22、systemd、可选 Caddy HTTPS） |
| `worker/agent.js` | 客户端核心：报平安、按设置挂机、领活、跑配方、上传存档、被叫停 |
| `worker/probe.js` | 体检：nvidia-smi、内存、硬盘、网速；别的程序在不在用显卡 |
| `py/lg.py` | 配方用的小工具；还会每 0.25 秒看一眼主线程执行到配方的第几行（界面上高亮） |
| `shared/expr.js` | 捞捞「表情参数」标准 v1：14 个参数，画图和声音都按它走 |
| `app/` | Electron 客户端：星图、实时面板、任务向导、录表情（`record.html`，MediaPipe face_mesh）、审核、贡献榜 |
| `tools/grid.js` | 管理员命令行：登录、签名上传配方、按计划建任务、发邀请、设自动训练 |
| `server/cycle.js` | 自动训练（不定时间：一直有活、审核攒够就训练）/ 每日一轮（定时）；评测过了才发布、老师端的发布清单 |
| `app/ai.js` | AI 引擎（ComfyUI）：一键装、给配方画图；代码和捞捞PPT助手共用（打包时从 `pptassist/core` 拷到 `app/ppt/`） |

测试：`npm test`（调度中心、断电测试、客户端）。界面截图：`node test/ui-server.js 8901 8902` 起一套模拟的训练网，浏览器打开 8901（客户端，要 `test/lg-shim.js`）和 8902/admin/（控制中心）。
