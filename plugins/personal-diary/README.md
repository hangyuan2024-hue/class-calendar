# 个人日记模块（Personal Diary）

## 1. 模块说明
这是“班级群信息整理助手”中的个人日记模块。模块为独立 HTML 页面，无需后端即可运行，适合直接嵌入或接入现有前端项目。
现已升级为 **图文情绪手帐系统**：每日心情 + 图文 Block 手帐 + 本地照片库。

## 2. 主要功能
- 每个自然日对应独立日记，默认打开当天。
- 支持前一天、后一天、日期选择器和“今天”按钮切换日期。
- 日记内容自动保存，切换日期前会先保存当前内容。
- 支持历史日记列表、字数/图片数统计。
- 支持浅色/深色系统主题和移动端适配。
- 支持天气记录：
  - 今天：可查询并保存当前选择城市的当天实时天气。
  - 历史日期：若已有天气记录，优先恢复该日已保存的城市和天气。
  - 历史日期无天气记录时，不自动猜测城市；补写日记时提示用户手动选择城市（停笔约 2.5 秒后弹出，不打断输入），再查询该城市在该历史日期当天的天气。
  - 历史日期可主动修改城市，修改后会重新查询该城市在该日期当天的天气并覆盖该日天气记录。
  - 支持浏览器定位；定位只在用户主动授权后使用。

### 2.1 每日心情（新增）
- 位置：天气区域下方、手帐编辑区上方，标题“今天的心情”（浏览历史日期时显示“当天的心情”）。
- 8 个带 emoji 的心情按钮：😀 开心 / 😌 平静 / 🥰 幸福 / 🤩 兴奋 / 😴 疲惫 / 😔 难过 / 😟 焦虑 / 😡 生气。
- 手帐风格按钮：圆角、柔和背景、点击缩放动画；选中后高亮并显示 🟡 标记。
- 每天只保留一个主要心情，可随时修改，再点一次可取消；切换日期自动恢复当天心情。
- 历史日记列表中直接显示当天心情 emoji。

### 2.2 图文手帐编辑（新增）
- 编辑区由 textarea 升级为 Block 编辑器，内容由多个块按顺序组成：文字 ↓ 图片 ↓ 文字 ↓ 图片。
- 文字块：可直接输入，回车换行；粘贴自动转为纯文本。
- 📷 添加照片：支持本地多选（一次最多 9 张）、剪贴板粘贴、拖拽文件到纸面；图片不上传服务器。
- 照片编辑：鼠标/触摸拖动（pointerdown / pointermove / pointerup）、四角缩放手柄（保存 width / height，等比缩放）、右上角 × 删除（页面元素 + 本地照片库一起删除）。
- 手帐视觉：横线纸张、拍立得白框、图片阴影、圆角、胶带、按日期稳定生成的小贴纸、照片轻微旋转。
- 照片入库前会等比压缩（最长边 1600px，JPEG），控制体积。

### 2.3 全页面笔迹动效 TextCursor（新增）
- 来源：React Bits 微组件 `TextCursor`（JS + CSS 版，https://reactbits.dev/micro/text-cursor ）。
- 作用范围：**整页**。动效挂在 `body` 的固定浮层 `.text-cursor-layer` 上，页面任意位置（标题、日期卡片、心情区、手帐纸、留白处）移动鼠标都会沿轨迹落下笔迹。
- 效果：手帐风格笔迹点 `✎`，每个点按鼠标方向旋转并带轻微随机浮动；鼠标停下后逐个淡出回收。
- **不干扰任何操作**：浮层是 `pointer-events:none` + `aria-hidden`，不拦截点击、拖拽、选择与滚动；实测照片拖动、按钮点击、日期切换全部照常。
- **编辑文字时自动静默**（重要）：当焦点落在文字编辑区（手帐 `contenteditable`、日期输入框、城市输入框等 `input / textarea / select`）时，不产生新笔迹，并立即清空已显示的笔迹，避免笔迹盖在正在输入的字上。点击页面空白处失焦后自动恢复。
- 设备条件：仅在「桌面端精确指针 + 支持 hover」的设备挂载。
  - 触摸设备（手机 / 平板）完全不挂载浮层，页面保持普通文字，不会出现异常光标。
- 参数（`TC_OPTIONS`，位于“模块 19：TextCursor 动效”）：

  | 参数 | 原版默认 | 本项目取值 | 说明 |
  | --- | --- | --- | --- |
  | `text` | `⚛️` | `✎` | 改为手帐笔迹字符，贴合纸张风格 |
  | `spacing` | `100` | `90` | 每移动 90px 落一个点，比默认略密 |
  | `followMouseDirection` | `true` | `true` | 笔迹随鼠标方向旋转 |
  | `randomFloat` | `true` | `true` | 每个点带 ±5px / ±5° 随机浮动 |
  | `exitDuration` | `0.5` | `0.5` | 淡出时长（秒） |
  | `removalInterval` | `30` | `30` | 静止后每 30ms 回收一个点 |
  | `idleBeforeRemoval` | 无（原版硬编码 100ms） | `350` | 停笔后多久开始回收；原版 100ms 太短，笔迹几乎一闪而过 |
  | `maxPoints` | `5` | `4` | 同时存活点数，压低 DOM 数量 |

- 关于系统「减弱动效」（`prefers-reduced-motion: reduce`）：
  - **Windows「设置 → 辅助功能 → 视觉效果 → 动画效果」一旦关闭，Chrome / Edge 就会把 `prefers-reduced-motion` 报成 `reduce`**，此时若直接禁用动效，会在完全正常的桌面鼠标设备上"静默失效"，表现为"这个动效无法实现"。
  - 因此本项目的策略是**降级而非关闭**：检测到 `reduce` 时自动改用 `TC_OPTIONS_CALM`（不浮动、不旋转、点数更少），笔迹照常可见。
  - 如需严格遵循系统偏好、完全不显示，把 `TC_RESPECT_REDUCED_MOTION` 改为 `true` 即可。
- 排查入口：浏览器控制台执行 `textCursorStatus()`，会直接告诉你当前是否挂载、处于哪种模式、以及未生效的原因。

- 性能与生命周期：
  - `mousemove` 监听以 `{ passive: true }` 挂在 `document` 上，只登记坐标，实际补点合并到下一帧 `requestAnimationFrame` 执行（高频移动不会卡顿，也不影响滚动）。实测 200 次事件处理耗时 < 1ms。
  - "是否正在编辑"只在 `focusin / focusout` 时重算一次，避免每次鼠标移动都做样式查询。
  - 坐标直接使用 `e.clientX / e.clientY`（视口坐标），与浮层的 `fixed` 定位一致，滚动页面时笔迹依然精确跟随鼠标。
  - 存活笔迹点受 `maxPoints` 约束；正在淡出的节点会短暂驻留，DOM 总数始终有界。
  - 页面卸载（`pagehide`）时统一 `destroy()`：移除监听、清掉定时器与 rAF、摘除整个浮层，无内存泄漏。
  - 动效初始化失败会被 `try/catch` 兜住，不影响日记任何既有功能。

### 2.4 自定义日历：日期格带心情背景（新增）
- **为什么不用原生日历**：点击原生 `<input type="date">` 弹出的日历由**浏览器内核绘制**，属于浏览器自身的 UI，CSS 和 JS 都无法往里注入内容，所以"给原生日历的日期格加心情背景"在技术上无法实现。
- 因此本项目**自建日历弹层**替代它：
  - 每个日期格把「当天记录的心情 emoji」作为**半透明背景**（`opacity: .32`），日期数字始终清晰可读。
  - **当天没有记录心情时，只显示日期数字**（不显示任何 emoji）。
  - 今天用主色描边标出；当前选中日期用主色填充。
  - 非本月的日期（补位格）用次要色显示，仍可点击跳转。
  - 顶部 `« ‹ 2026年9月 › »` 支持翻月 / 翻年；底部有「回到今天」。
- **兼容性处理**：原生 `#datePicker` 仍然保留在页面上，位置、尺寸、`value`（`YYYY-MM-DD`）全部不变，其他逻辑照旧读 `el.picker.value`；只是上面盖了一层透明按钮接管点击，因此**原生日历不会再弹出**，也不会出现两套日历同时存在的情况。
- 交互：点击日期框展开/收起；点击日期格切换日期并自动收起；点击弹层外部或按 `Esc` 收起；支持方向键在日期格间移动焦点、回车选中；`aria-expanded` / `aria-current` / `aria-label` 同步更新（`aria-label` 会带上当天心情，如"2026年9月30日，开心"）。
- 心情数据来源：直接读取 `personal_mood_YYYY-MM-DD`，与心情模块共用同一份数据，心情改动后重新打开日历即可看到背景同步（含取消心情后背景消失）。

## 3. 数据存储
数据仅保存在当前浏览器的 `localStorage` 中（照片存 IndexedDB），不依赖服务器数据库。

主要键包括：
- `personal_diary_page_YYYY-MM-DD`：某日图文手帐整页（文字块 + 图片块 + 心情 + 天气，AES-GCM 加密）
- `personal_diary_YYYY-MM-DD`：某日纯文字正文（旧格式，仍会同步写入，保证旧数据/旧版本可读）
- `personal_mood_YYYY-MM-DD`：某日心情 `{date, mood, emoji, label, updatedAt}`
- `personal_diary_weather_YYYY-MM-DD`：某日天气快照
- `personal_diary_key`：本地 AES-GCM 密钥材料
- `personal_diary_meta`：日记日期、最后更新时间、照片数元数据
- `personal_weather_city`：最近使用城市
- `personal_weather_lat` / `personal_weather_lon`：最近使用城市坐标
- `personal_weather_cache`：天气缓存
- `personal_photo_<id>`：照片兜底存储（仅当 IndexedDB 不可用时写入 dataURL）

照片库：
- IndexedDB 数据库 `personal_diary_db`，对象仓库 `photos`（keyPath: `id`，索引 `day`）。
- 记录结构：`{ id, day, blob, type, createdAt }`。

注意：清除浏览器站点数据、localStorage、IndexedDB 或更换浏览器/设备后，本地日记数据不会自动同步。

## 4. 天气服务
天气与城市查询使用 Open-Meteo 相关接口；浏览器定位后的城市名称解析使用公开反向地理编码接口。天气功能需要联网，但天气接口失败不会影响日记输入和本地保存。

## 5. 运行方式
直接用现代浏览器打开 `2.html` 即可运行。

本项目是**零依赖单文件页面**：没有 `package.json`、没有构建步骤，因此**不存在 `npm install` / `npm run build`**。
所有第三方能力（含本次的 TextCursor）都是按官方源码 1:1 移植为原生 DOM + CSS，不引入任何运行时依赖。

建议浏览器：
- Chrome / Edge
- Android Chrome
- Safari（支持 Web Crypto 的版本）

## 6. 集成建议
如果接入主项目，可将该页面作为独立页面接入路由，或拆分其中的 HTML/CSS/JS 后并入现有前端结构。

若目标主项目本身是 React + Tailwind 工程，可以直接用官方方式接入 TextCursor 原版组件，而不必使用本页的移植版：
```bash
npx shadcn@latest add @react-bits/TextCursor-JS-CSS
npm i motion@^12.23.12
```
原版组件源码已一并归档在 `react-bits/TextCursor/` 下，可直接拷贝使用。

集成时请保留：
- `personal_` 本地存储前缀
- 日期独立存储逻辑
- 天气按日快照逻辑
- Web Crypto 加密逻辑
- 照片仅存本机（IndexedDB）不上传的约定
- TextCursor 的设备能力判断（触摸设备 / 减弱动效下不挂载）
